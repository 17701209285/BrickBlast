# 导出工程关卡配置梳理

## 1. 范围

本文件整理的是以下目录里的关卡配置线索：

- `E:\workspace\export_unity\Brick+Blast_unity_project`

这不是目标工程 `E:\workspace\Projects\BrickBlast\Client` 里的自制关卡资产，而是导出出来的原始 Brick Blast 工程线索。

## 2. 结论

导出工程里能确认到三类“关卡/地图配置”来源：

- 主线关卡：代码里明确约定读取 `levels/main1.ebr`，但当前导出目录里没有实际落地的主线 `.ebr` 包
- 日挑战关卡：有一份本地配置表，记录了 12 个远端 `dc-blueprint/*.ebr` 文件地址
- `gradual` 配置：本地确实落了一份 `gradual.ebr.bytes`，但它不是主线关卡包

也就是说：

- 主线关卡“读取规则和数据结构”能看出来
- 主线关卡“实际内容”在当前导出目录里没有还原出来

## 3. 主线关卡读取入口

主线关卡路径定义在：

- `ExportedProject/Assets/Scripts/Assembly-CSharp/Easybrain/BrickBlast/Scripts/Constants.cs`

关键常量：

- `StreamingAssetsLevelsDirectory = "levels"`
- `DefaultLevelSequenceId = "main1"`
- `DefaultLevelSequencePath = "levels/main1.ebr"`
- `EgasLevelsPrefix = "bblevels_"`

这说明主线默认会尝试读取：

- `levels/main1.ebr`

同时还存在一个远端包命名前缀：

- `bblevels_`

说明主线关卡除了内置包之外，也带有通过 EGAS / 配置下发更新包的能力。

相关代码线索：

- `ExportedProject/Assets/Scripts/Assembly-CSharp/Easybrain/BrickBlast/Scripts/Game/LevelsSequence/LevelsSequenceProvider.cs`
- `ExportedProject/Assets/Scripts/Assembly-CSharp/Easybrain/BrickBlast/Scripts/Parameters/GroupParameters/Levels.cs`
- `ExportedProject/Assets/Scripts/Assembly-CSharp/Easybrain/BrickBlast/Scripts/DataSave/GameProfile/GameProfileData.cs`

可看出：

- 配置参数里有 `pack`
- 存档里有 `LevelsSequenceId`
- 关卡序列存在“默认 main1”和“可切换包”的逻辑

## 4. 主线关卡数据结构

### 4.1 关卡序列

`LevelsSequenceData` 定义在：

- `ExportedProject/Assets/Scripts/Assembly-CSharp/Easybrain/BrickBlast/Scripts/DataSave/Binary/LevelsSequenceData.cs`

字段很简单：

- `Sequence : List<byte>`

说明它保存的是一串关卡序列信息，但具体 byte 到难度/关卡的映射逻辑要配合运行时解析。

### 4.2 单关地图

`FieldModelData` 定义在：

- `ExportedProject/Assets/Scripts/Assembly-CSharp/Easybrain/BrickBlast/Scripts/DataSave/Binary/FieldModelData.cs`

字段如下：

- `Width`
- `Height`
- `Blocks`
- `Triggers`
- `BallsCount`
- `TriggerHits`
- `Difficulty`
- `Version`
- `MinVersion`

这说明 `.ebr` 里至少会保存：

- 棋盘尺寸
- 普通砖块数据
- 特殊触发器数据
- 球数量
- 触发器命中记录
- 难度和版本号

## 5. 当前导出目录里实际落地的包

### 5.1 没有找到主线 `main1.ebr`

当前目录下没有找到：

- `StreamingAssets` 目录
- `levels/main1.ebr`
- 任何主线 `levels/*.ebr` 包

所以可以确认：

- 主线默认包名虽然写在代码里
- 但这份导出目录没有把主线包明文还原出来

### 5.2 唯一能确认落地的 `.ebr` 包是 `gradual`

当前能直接找到的本地 `.ebr` 资源只有：

- `ExportedProject/Assets/TextAsset/gradual.ebr.bytes`

它被以下资源引用：

- `ExportedProject/Assets/MonoBehaviour/GradualConditionsSettings.asset`

`path_id_map.json` 里也只索引到了这一条：

- `AuxiliaryFiles/path_id_map.json` 中的 `gradual.ebr`

把 `gradual.ebr.bytes` 的包头解出来后，能看到：

```json
{"package_name":"gradual","compress":true,"categories":[{"category":"","count":1}],"resources":[{"name":"ebr_content","path":"/ebr_content.json"},{"name":"gradual","path":"/gradual"}]}
```

这说明：

- 它确实是一个 EBR 包
- 包名叫 `gradual`
- 但它不是主线 `main1`
- 更像是“渐进条件 / 节奏控制”相关配置包

## 6. 日挑战关卡配置

日挑战配置文件在：

- `ExportedProject/Assets/MonoBehaviour/DailyChallengeLocalContentSettingsAndroidRelease.asset`

这份资产里保存了：

- 一组 `Content` 日期与 `FileId`
- 一组 `Files`，把 `FileId` 映射到 `.ebr` 地址
- 一组 CDN 根地址

当前可见共有 12 个 blueprint 文件：

- `dc-blueprint/1/*.ebr`
- `dc-blueprint/2/*.ebr`
- ...
- `dc-blueprint/12/*.ebr`

CDN 地址：

- `https://s3-ca-rcs.easybrain.com`
- `https://s3.ca-central-1.amazonaws.com/s3-ca-rcs.easybrain.com`

说明日挑战不是把完整关卡内容都内置在本地，而是：

- 本地保留一份“日期 -> 文件 ID -> 远端 .ebr 地址”的配置表
- 实际蓝图内容依然依赖远端 `.ebr`

## 7. 活动地图 / 事件关卡

事件相关配置线索：

- `ExportedProject/Assets/MonoBehaviour/EventsCoreFeatureConfig.asset`
- `ExportedProject/Assets/MonoBehaviour/EventCoreSettingsNetwork.asset`

能看到：

- `_mapsSimpleFeatureConfig: {fileID: 0}`
- 活动配置接口走 `https://api-liveops.easybrain.com/api/v2/event_core`
- CDN 接口走 `https://api-liveops.easybrain.com/api/v2/coord`

这说明当前导出目录里：

- 事件地图没有落一份明确的本地关卡配置实例
- 更像是由 liveops 在运行时远端下发

## 8. 现有工具类说明

导出工程里还保留了几类“关卡包处理工具”的代码壳：

- `LevelsPackValidator.cs`
- `LevelsPackComparer.cs`
- `LevelSequenceReverseConverter.cs`

从命名上可以判断它们原本用于：

- 校验 `.ebr` 包
- 对比两份关卡包差异
- 把 `.ebr` 反解回旧表示或 JSON

但当前导出代码的方法体大多是空壳，无法直接靠这份代码把缺失的主线包反编回来。

## 9. 当前能确定与不能确定的内容

### 9.1 能确定

- 主线默认包名是 `main1`
- 主线默认路径是 `levels/main1.ebr`
- 主线 `.ebr` 的核心数据结构是 `LevelsSequenceData + FieldModelData`
- 本地确实有一份 `gradual.ebr.bytes`
- 日挑战配置里记录了 12 个远端 `.ebr` 蓝图地址
- 事件地图大概率是远端 liveops 下发

### 9.2 不能从当前目录直接拿到

- 主线 `main1.ebr` 的真实内容
- 主线完整关卡列表
- 主线每关的具体砖块布局
- 日挑战 `.ebr` 实际内容
- 事件地图实际内容

## 10. 如果继续追

如果还要继续往下挖，下一步最有价值的是：

- 从原始 APK / OBB / 安装包里继续找 `levels/main1.ebr`
- 直接把日挑战 `.ebr` 远端地址批量拉下来分析
- 如果能拿到任何主线 `.ebr`，再用现有结构把它反解成关卡表
